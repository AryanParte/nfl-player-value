## What changed and why

A read-only build job restores the previous retained candidate, captures the four
sources, checks completed-game coverage/freshness, builds an isolated website,
packages its exact dependencies and tests the restored site in Chromium. The
publisher independently binds the package hash and workflow revision, checks
current readiness and creates a new draft release. It downloads the remote assets
into a separate directory, compares exact bytes and replays them before exposing
the archive. Only then can Pages receive the verified site, after another fresh
check. Failed earlier steps do not request a website deployment.

Content-addressed release tags retain original/corrected versions without asset
overwrites. The previous **retained** candidate may differ from the last deployed
website; its game set conservatively constrains the next candidate. Public release
metadata does not claim that deployment succeeded. Workflow concurrency covers
the whole transaction. Bootstrap is explicit and cannot reset existing retention
history; an API failure cannot masquerade as an empty release list.

The twice-weekly production trigger is Tuesday/Friday 16:17 UTC and only runs on
canonical main. It is independent of Codex's 7:30 PM development heartbeat.
There are no new Python/npm dependencies, secrets, services, purchases or upgrades.
The build/publisher have 30/20-minute limits; public standard GitHub runners/Pages
are the intended zero-cost route. Retention growth must still be monitored.

## Concepts and critical review

An integrity hash establishes which bytes were used. It does not establish their
freshness, explain why a defender caused an outcome, or validate an uncertainty
interval. Restoring an archive reproduces the recorded decision; publication must
check the actual attempt time again. Likewise, a copied old website cannot become
current-workflow output just because a newer packager wraps it. An additional
regression explicitly protects that producer binding.

Self-review inspected the full implementation/diff, permission boundaries,
retention/publication ordering, draft failures, bootstrap recovery, site paths,
missingness and statistical labels. Browser assertions wait for all 17 module
decisions to load, avoiding a false pass while availability is still pending.
No benchmark, qualification threshold, model, uncertainty method or admission
decision changed. CAVAA/snaps remain null; 4 sacks, 2 names and 16 defensive chart
cells retain missingness. Observed event counts are not individual value scores.
