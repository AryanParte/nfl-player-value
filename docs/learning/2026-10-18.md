# October 18, 2026 — foundation and benchmark contracts

## What was built and why

Created the independent repository and stable clone, persistent research/design
documentation, package scaffold, offline tests and CI. The first working unit
turns benchmark construction and leaderboard qualification into executable
contracts. These decisions change every later ranking, so they need explicit
inputs and failure behavior before we fit a model.

The code does not calculate real player scores yet. Synthetic model predictions
exercise the comparison arithmetic without masquerading as NFL observations.

## Statistical ideas

An average is a population plus weights. The primary benchmark gives each team
equal total weight, averages its completed games, and splits each role's game
weight among pregame first-unit members. A bye therefore does not reduce a team's
overall influence, and a one-game first-unit player does not receive a full-season
starter's weight.

Equal-player sensitivity includes everyone with at least one valid observed role
opportunity, even if ineligible for the leaderboard. Opportunity weighting instead
describes performance encountered on a typical observed opportunity. An unused
roster member cannot move the equal-player sensitivity merely by having a model
prediction. A first-unit player with zero opportunities can still appear in the
primary comparison when a valid partially pooled prediction is available.

Qualification is not estimation. The model may learn from a reserve's handful of
plays even when that player cannot qualify for MVP display. Likewise, enough snaps
do not demonstrate that a defender's effect is identifiable or comparable with
an offensive estimate. Source coverage, attribution validation, and comparability
are independent gates. No gate selects for positive estimates or narrow intervals.

## Engineering decisions and self-review

The initial package has no runtime dependencies; standard-library dataclasses and
unit tests keep these deterministic contracts easy to inspect. Modeling libraries
will enter when needed and validated. CI tests package installation and Python
3.11–3.13. The build backend and CI actions are pinned.

Review corrected the equal-player population so zero-opportunity predictions do
not dilute it, and removed double rounding in fractional snap thresholds. An
independent review identified missing regular-season scope; the completed-game
contract now rejects preseason/postseason inputs and invalid regular-season weeks.

The development lease uses atomic directory creation in the Git common directory.
It persists across individual tool calls, unlike a shell-only lock. Tests exercise
simultaneous claims, linked worktrees, wrong tokens and interrupted metadata writes.
The lock is advisory, cannot expire automatically, and does not serialize unrelated
repositories. The separate evening schedule reduces contention with the existing
morning project; expensive fitting must still consider host load.

## Verification and limits

Local verification passed: **27 tests**, source compilation, all repository
documentation links, staged whitespace checks, and installation of the pinned
package in an isolated environment. The PR and CI record carry remote check
