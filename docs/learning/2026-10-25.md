# October 25 — A Defense Explorer with inspectable evidence

## What changed and why

Implemented the required Defense Explorer foundation and the first dark,
responsive React/TypeScript dashboard. Users can search players, filter observed
teams and chart roles, inspect game evidence, compare signed team EPA over games,
see blocked role coverage, and inspect/download the exact saved snapshot. Missing
measurements remain visible. This makes the defensive workstream useful while its
individual attribution problem remains unresolved.

The Python producer rebuilds observations from the existing archived 2026 outcome,
chart and roster receipts. The snapshot contains 518 players, 93 completed games
and 11,441 included pass/run plays through Week 6. It records 425 valid sack credits
and 130 interceptions. Four flagged sacks are unallocated, 92 player chart roles
are unverified, one name is unresolved, and ten defensive team-game-role cells are
blocked. All 186 chart team-games use retrospectively retrieved chart evidence.
These are scope/coverage findings, not player rankings.

The cutoff remains October 22, 2026 at 23:50:38.680415 UTC. This unit performs no
fresh source capture and makes no claim to include games completed since then.
See [the measured audit](../audits/2026-10-25-defense-explorer.json) and
[data contract](../DEFENSE_EXPLORER.md). The site is usable locally and is not yet
deployed. No 2026 CAVAA score or uncertainty interval is published.

## Architecture decisions

The Python pipeline owns numerical observations and provenance. React renders a
static JSON export rather than calculating a score or calling live NFL sources.
No database, application API, commercial feed or hosted service is needed. The
producer commit is `7e6c0ff6553a085e37559babbf8b1862578c0c8e`; the recorded export
report is `497f59523ffd5f608937d82dda6a5d2abf1a8621d92ba7031df94b3a1f605435`.

The 807,547-byte payload is content-addressed and replayed exactly. Export writes
the immutable object before atomically advancing its latest pointer, preserving
prior objects. The browser checks its hash, then a strict Zod runtime contract and
cross-record totals. A TypeScript type alone cannot validate downloaded JSON.
The hash proves byte consistency, not the truth of the football data or the
identity of a compromised publisher.

Node 24, exact npm dependency pins and a committed lockfile make frontend builds
reproducible. Vite emits a static bundle; HTML/CSS with text equivalents is enough
for these two small charts. CI adds a separate frontend/Chromium job while keeping
the existing Python 3.11–3.13 matrix. Formatting is checked to keep UI changes
reviewable. Local browser/cache directories and ports belong only to this repo.
All generated source/export bytes remain outside Git, so durable off-machine
retention is still a release prerequisite.

## Statistical concepts

**An event is not a contribution estimate.** A sack is jointly produced by the
rusher, coverage, protection, quarterback and situation. Assigning a recorded sack
credit is a descriptive bookkeeping operation. It does not justify assigning the
whole play's EPA to that defender. A split sack conserves one credit by assigning
0.5 to each of two valid recorded identities; malformed identity records withhold
the event's credit while preserving its team outcome.

**The denominator determines what a rate means.** A chart-listed game is not proof
that a player took a snap. Event appearances are a lower bound on appearances,
not games played. This view therefore cannot calculate defensive snap fractions,
pass-rush pressure rates, absence exposure or leaderboard qualification. A zero
means no valid recorded credit in this scope, not zero football value or confirmed
absence. Team filtering recomputes totals from that team's evidence.

**Missingness is not an uncertainty interval.** We have deterministic recorded
counts with incomplete measurement, not admitted defensive CAVAA estimates with
sampling distributions. Arbitrary error bars would not restore unobserved coverage
assignments or pressure. Unknown roles and conflicting chart cells are disclosed;
they do not receive guessed positions or scores. The primary first-unit benchmark,
equal-player/opportunity sensitivities and separation of eligibility from benchmark
membership remain unchanged and are not evaluated by this product unit.

### Concepts and verification

A hash answers “are these the recorded bytes?”, not “are these correct results?”.
The new tests deliberately hash changed coefficients/components and verify that
reconstruction still rejects them. Allocation must replay as well as the total:
a player component changing by one EP cannot be hidden by an unchanged play total.
Neither this consistency check nor predictive performance proves causal player
attribution. The first-unit estimand, benchmark/eligibility separation and pending
position-admission decisions are unchanged.
